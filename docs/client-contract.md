# RPA 客户端协议与浏览器检查说明

本目录 `client/` 是技术方资料员的 Chromium RPA 客户端。它不生成离线申请文件，
所有写入都通过 Playwright 驱动真实页面点击“保存草稿/正式提交”，并把每次页面
动作、答复与受理依据留存在证据目录。

## 模块划分

| 模块 | 职责 |
| --- | --- |
| `client/model.py` | 字段身份、条件材料义务、申请意图/补正意图、完整性与材料差异规则 |
| `client/portal.py` | Chromium 页面适配：读页、按字段标识填写、点击保存、答复分类、落盘复核 |
| `client/workflow.py` | 编排：差异核对、冲突/答复丢失收敛、提交门禁、定向补正、历史查询 |
| `client/evidence.py` | 证据：动作日志、保存记录、受理回执、页面截图与 HTML 快照 |
| `client/exceptions.py` | 失效枚举、修订冲突、提交阻塞等可解释异常 |
| `client/cli.py` | 命令行入口 |

## 字段身份与条件义务

- 全程以稳定字段标识定位（`title/scopes/data_use/notice/mode`）。门户字段字典
  更新只改显示名称（“试验类型”→“运行类别”），字段身份不变，RPA 不按显示名定位。
- 院内 `hospital` 触发 `data_use` 字段与 `data` 材料；公共 `public` 触发
  `notice` 字段与 `points` 材料；任一范围存在即需要共用材料 `shared`。
  两类范围同时覆盖时义务取并集。
- 撤去某范围只撤去由它触发、且不再被其它范围需要的字段与材料；`shared` 仍供
  另一范围使用时保留。撤范围后页面上被隐藏的触发字段输入框会被显式清空，
  避免旧值随提交负载残留。
- 场景方字段 `owner/condition` 只读观察，保存负载只含五个技术方字段；
  客户端代码不引用演练控制端点 `__control`，不能代场景方确认。

## 枚举处理

下拉按 option 的稳定值选择。输入使用当前字典已淘汰的枚举（如字典更新后的
`pilot`）时抛出 `RetiredEnumError` 并阻断，绝不自动改成第一个选项；门户现有
值保持原样，由资料员显式改用新字典允许的值（`trial/production`）。

## 双方编辑相遇的保存收敛

保存负载携带打开页面时的修订号。工作流处理三类结果：

1. **成功**：页面返回 `saved_revision`，重读页面确认。
2. **修订冲突（409）**：场景方另一会话编辑递增了修订。重读页面取得对方新内容
   （场景方字段由门户保留，技术方负载本就不含它们），按最新修订重试，
   不新建另一份申请规避冲突。
3. **答复丢失（503 `gateway_after_save` / 超时 / 导航中断）**：不凭超时认定
   未保存。先重读页面复核目标内容是否已落盘：已落盘则收敛返回、不重复建档；
   未落盘则按当前修订重试。

## 提交门禁与确认的修订相关性

- 不完整内容可逐次保存为草稿；正式提交要求当前修订下字段与义务材料齐全，
  且场景方确认修订等于当前修订，否则分别抛出 `IncompleteDraft` 或
  `PartnerConfirmationRequired`。
- 确认针对具体申请修订：技术字段变化产生新修订后旧确认立即失效，范围变化
  同样使旧确认不适用。RPA 明确报“等待场景方确认”，不替合作方确认。
- 页面内容已与意图一致时提交不再触发保存，避免无变更保存制造新修订、
  使刚取得的确认失效。

## 定向补正

- 补正意图必须带原申请号；门户历史中不存在该申请号时拒绝（`unknown_application`）。
- 以页面当前技术字段为基底，仅覆盖补正指定字段，未受影响的已确认内容保留。
- 仅材料变更（不动技术范围）不递增修订、门户保留确认，可直接再提交；
  技术字段变化则保存后停在“等待场景方确认”。
- 受理后申请号 `APP-001` 保持稳定，历史区分 `accepted` 与 `corrected`，
  并记录 `corrected_fields`。

## 命令行

```bash
python -m client.cli --base http://127.0.0.1:8765 --evidence-dir runs/01 import --request inputs/request.json
python -m client.cli --base http://127.0.0.1:8765 reconcile --request inputs/request.json   # 只读，退出码 2=未就绪
python -m client.cli --base http://127.0.0.1:8765 --evidence-dir runs/01 submit --request inputs/request.json
python -m client.cli --base http://127.0.0.1:8765 --evidence-dir runs/01 correct --correction correction.json
python -m client.cli --base http://127.0.0.1:8765 history
```

退出码：0 成功；2 核对未就绪；3 提交被阻塞/等待场景方确认；4 失效枚举；1 其它 RPA 错误。

## 可重复的浏览器检查

`python -m unittest discover -s tests -v` 中 `tests/test_client.py` 启动真实
Chromium 驱动合成门户，覆盖：

1. 导入→只读核对→保存→确认→受理→历史的完整链路与证据落盘；
2. 场景方另一会话编辑条件造成 409，客户端保留对方新内容并按新修订重试，
   申请号稳定、不重复建档；
3. 字段字典更新后失效枚举被阻断且不兜底，显示名称变化不影响字段身份；
4. 撤去范围只裁剪本范围字段与材料，共用材料按另一范围需要保留；
5. 保存后 503 与导航中断均按“答复不确定”复核，不重建申请；
6. 确认按修订生效：技术字段变化后旧确认不放行；
7. 定向补正绑定原申请号、保留未受影响内容、`corrected` 受理；
8. 仅材料补正保留确认；未知申请号补正被拒绝；
9. 不完整草稿可存不可交；核对动作只读；客户端不触碰演练控制端点。
